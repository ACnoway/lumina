# AI 生图参考图与图片编辑

## 使用方式

在 AI 生图页选择支持参考图的模型，填写提示词，并按需上传一张图片。提示词可描述参考内容（例如“参考这张图的配色，画一座海边小屋”），也可描述修改要求（例如“将照片中的背景换成雪山，保留人物”）。参考图和反向提示词均为可选项，不上传时继续使用文字生图。

- 接受 JPEG、PNG、WebP，单张最大 5 MiB；浏览器检查 MIME 和大小，服务端同时核对文件签名。
- 点击参考图卡片的“上传参考图”选择图片，选图后可点击缩略图预览，通过“更换图片”替换或“移除参考图”移除；切换到不支持参考图的模型时，会移除当前选择并提示。卡片显示格式、5 MiB 限制和已选数量，选择图片在提交任务时上传；非法替换保留原有合法图片并就近提示错误。界面规范见 [用户端 UI 优化](ui-polish.md)。
- 支持一次生成 1–4 张结果，所有结果使用同一张参考图；继续按成功输出的图片张数计费。
- 生成结果及历史记录展示原参考图，可打开预览。提示词优化仍只处理文字，编辑场景下应检查优化后的文字是否保留修改意图。

## 模型配置

管理员进入“模型与供应商 → 平台模型”，新建或编辑 `IMAGE` 模型，勾选“此模型支持参考图 / 图片编辑”。配置字段为 `supportsReferenceImage`，默认 `false`，独立于聊天模型的 `supportsVision`。

只有生图模型可开启参考图能力；切换为聊天模型时后端自动关闭此项。管理员必须确认该平台模型下**所有启用的上游映射**均支持参考图。开关只声明能力，不会使不支持图片编辑的上游获得该能力。未开启时，携带参考图的请求返回 400，且不创建任务、不上传对象、不计费。

## API

`POST /image/generate` 兼容已有 JSON 文字请求；携带参考图时使用 `multipart/form-data`，不要手动指定 multipart boundary。

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `prompt` | 是 | 生成描述或图片修改要求，最多 4000 字符 |
| `model` | 是 | 已启用的 IMAGE 平台模型名 |
| `referenceImage` | 否 | 一个 JPEG、PNG 或 WebP 文件，最大 5 MiB |
| `negativePrompt` | 否 | 反向提示词，上游是否生效取决于接口能力 |
| `originalPrompt` | 否 | 优化前的提示词 |
| `aspectRatio` | 否 | `1:1`、`9:16`、`16:9`、`4:3`、`3:4`，默认 `1:1` |
| `imageCount` | 否 | 输出数量 1–4，默认 1；multipart 中传数字字符串 |

任务创建、状态及历史接口新增 `referenceImage`，没有参考图时为 `null`，否则为 `{ url, mimeType, size }`。接口只返回当前用户任务的参考图元数据；每次读取重新签发有效期 7 天的对象访问 URL。

## 上游与存储

- `openai_image`、`openai_compatible`：有参考图时调用 `/images/edits`，以 multipart 的 `image` 文件字段传递原始图片和提示词；无参考图保持 `/images/generations`。编辑响应兼容 URL 和 `b64_json`，不强制指定 `response_format`，支持上游默认返回 Base64。协议依据 [OpenAI 官方图片编辑接口](https://developers.openai.com/api/reference/resources/images/methods/edit)。
- GPT Image 系列文字生图同样不强制请求 URL 格式。GPT Image 1 系列仅接受固定尺寸，非正方形请求按方向映射为 `1536x1024` 或 `1024x1536`，记录相应尺寸；其他上游沿用既有比例尺寸映射。
- `stability_image`：沿用 `/v2beta/stable-image/generate/{model}`，额外传 `image`、`mode=image-to-image` 和 `strength=0.7`。只应对支持这些参数的上游开启参考图，不能给纯文字生图端点启用；参见 [Stability 官方 API](https://docs.stability.ai/api-reference)。
- 参考图上传至已启用的 S3 兼容对象存储，数据库记录对象 key、MIME 和大小；任务重试及重启恢复从对象存储重新读取原图，不依赖浏览器或临时文件。
- 任务写入失败会尝试清理已上传对象；入队失败时保留失败任务及参考图用于历史展示。切换存储 Endpoint/Bucket 时，参考图随生成图片、聊天附件一同迁移。
- 数据库迁移：`20261022030000_image_reference`，新增模型能力字段及任务参考图三项元数据；既有模型默认关闭，既有纯文字任务兼容。
