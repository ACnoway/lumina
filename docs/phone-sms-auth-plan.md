# 手机号与短信验证码认证方案

## 1. 业务规则

### 注册

- 默认使用“邮箱验证码注册”。
- 可切换为“短信验证码注册”。
- 支持仅邮箱注册、仅手机号注册，以及邮箱和手机号同时注册。
- 至少完成一种验证方式。
- 密码规则继续沿用现有规则。

### 登录

- 默认使用“邮箱或手机号 + 密码登录”。
- 可切换为手机号 + 短信验证码，或邮箱 + 邮箱验证码。
- 密码登录的账号输入框同时支持邮箱和手机号。
- 现有邮箱登录接口尽量保持兼容。

### 老用户

- 现有邮箱用户仍可使用邮箱密码或邮箱验证码登录。
- 未绑定手机号的老用户，需要在个人中心完成手机号绑定后才能使用短信登录。

## 3. 短信渠道架构

按照现有支付渠道模式实现：

```text
SmsChannelService
        ↓
SmsAdapterRegistry
        ↓
SmsChannelAdapter
        ├── MockSmsAdapter
        ├── AliyunSmsAdapter
        ├── TencentSmsAdapter
        └── ChuanglanSmsAdapter
```

通用 Adapter 负责：

- 渠道类型和能力描述；
- 配置校验；
- 发送验证码；
- 渠道连通性测试；
- 公共配置脱敏输出。

创蓝 Adapter 使用统一应用 AppID/AppSecret 模式，按 `SHA1(AppSecret + Nonce + CurTime)` 生成鉴权头，通过模板发送验证码。Lumina 的登录、注册和绑定验证码均使用创蓝 `verify` 产品类型；须预先在创蓝控制台申请并审核该产品类型下的模板。配置字段为 `appId`、`appSecret`、`templateCode`，可选 `endpoint`（默认 `https://smssh.253.com`，仅允许 HTTPS 域名基础地址）。发送使用 `/sms/v2/batch-send`，验证码按 `param1` 传入模板变量；国内手机号发给创蓝时去掉 `+86`，改用 11 位号码。验证码为安全随机生成的 6 位数字，实际有效期 300 秒；模板只包含一个 `{s}` 变量，变量长度至少 6 位，固定文案使用 5 分钟。管理端“验证配置”调用模板详情接口验证鉴权、审核状态、变量数量和长度，不发送短信。创蓝白模板匹配错误 `201124` 会保留在后端诊断中；公开发送接口返回 503 和安全的配置错误提示，管理接口返回可操作的详细原因。详细证据和配置示例见 [创蓝短信排障](sms-chuanglan-troubleshooting.md)。

每个具体短信供应商单独实现 Adapter，不让认证模块直接依赖供应商 SDK。

敏感配置使用独立的短信配置加密密钥，不直接暴露 AccessKey、Secret、模板签名等信息。

## 5. 短信发送流程

认证服务负责：

- 生成验证码；
- 生成 Redis key；
- 设置 5 分钟有效期；
- 设置 60 秒发送冷却；
- 单次消费验证码；
- 校验手机号、账号状态和注册用途。

短信渠道只负责“发送”，验证码不会交给前端，也不会写入数据库。

同时增加：

- 手机号维度限流；
- IP 维度限流；
- 错误验证码失效；
- 手机号日志脱敏；
- 防止通过错误信息枚举注册用户。

## 6. 注册流程

### 邮箱注册

1. 输入邮箱；
2. 发送邮箱验证码；
3. 默认完成邮箱验证；
4. 设置密码；
5. 创建用户和钱包。

### 手机号注册

1. 输入手机号；
2. 选择已配置的短信渠道发送验证码；
3. 验证短信验证码；
4. 设置密码；
5. 创建没有邮箱的用户和钱包。

如果同时填写邮箱和手机号，只验证用户选择的主验证方式，另一项后续单独绑定或验证。

## 11. 已落地接口与兼容约定

- 认证接口保留旧的 `email` 参数，同时接受 `account`；`account` 会被识别为邮箱或 E.164 手机号。
- `POST /auth/send-code` 和 `POST /auth/register/send-code` 根据输入选择邮箱或短信渠道；登录手机号不存在时返回通用提示，不通过错误文案枚举账号。
- `POST /auth/password-login` 支持邮箱或手机号密码登录，`POST /auth/login` 支持邮箱验证码或短信验证码登录。
- `POST /auth/phone/send-code` 与 `PATCH /auth/me/phone` 用于登录用户绑定/更换手机号。
- 管理接口位于 `/admin/sms-channels`，包括 `/adapters`、列表、创建、更新、`/:id/enable`、`/:id/disable` 和 `/:id/test`。
- Mock 渠道的验证码只短暂存储在 Redis，方便 E2E 读取；生产环境可启用阿里云、腾讯云或创蓝渠道，并使用独立的 `SMS_CONFIG_ENCRYPTION_KEY`。创蓝须提供统一应用 API Key，并配置已审核的 `verify` 类型模板。
