# AI 聊天图片输入

## 功能约定

- 聊天消息可附带最多 4 张图片，也可只发图片。
- 每张图片最大 5 MiB；单条消息图片总大小最大 20 MiB。
- 接受 JPEG（`.jpg`、`.jpeg`）、PNG 和 WebP。浏览器按 MIME 类型预筛选，后端还会核对文件签名与 MIME 类型。
- 图片通过当前已启用的 S3 兼容对象存储保存。数据库只记录对象 key、MIME 类型和字节数；历史接口按需返回有效期为 7 天的预签名访问 URL。
- 图片对象与聊天消息关联；删除会话时级联删除附件记录并尝试删除对象。对象存储配置切换会一并迁移聊天图片。
- 图片输入默认关闭。管理员在“模型与供应商 → 平台模型”编辑聊天模型并勾选“此模型支持图片输入”后，用户才可向该模型发图。上游模型也必须支持识图。
- OpenAI 兼容上游接收 Base64 Data URL 图片块；Anthropic 上游接收 Base64 图片块。历史上下文中的图片也会继续传给上游。
- 图片占用量按每张图片预估 1000 个输入 token 参与预扣；最终仍根据上游返回的实际 token 用量结算。

## 前端入口

聊天输入区通过“＋（添加附件）→ 上传图片”选择图片；入口展示支持格式、单图大小和数量限制。选择后显示缩略图、MiB 大小与已选数量，发送时才实际上传。模型选择区标注“支持图片／仅文字”；不支持图片、未选模型或达到 4 张上限时显示明确说明。

本次选图失败不会加入非法图片，也不会阻止已有合法附件或纯文本发送。若已选图片后切换到仅文字模型，需切回支持图片的模型或移除附件。该菜单目前只支持图片，尚不支持其他文件。完整 UI 约定及远程验证见 [用户端 UI 优化](ui-polish.md)。

## API

`POST /chat/messages` 保持原有 SSE 响应，将请求体改为 `multipart/form-data`：

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `sessionId` | 是 | 当前用户有权访问的聊天会话 |
| `model` | 是 | 已启用且允许图片输入的聊天模型（图片消息） |
| `content` | 否 | 最多 10000 个字符；可与图片同时发送 |
| `images` | 否 | 重复字段，最多 4 个图片文件 |
| `temperature` | 否 | 模型温度 |
| `maxTokens` | 否 | 最大输出 token |

首次 SSE 事件 `accepted` 会带回本条消息图片的 `id`、`mimeType`、`size` 和预签名 `url`；后续 `content`、`done`、`error` 事件保持原有格式。历史消息的 `attachments` 包含相同图片元数据和访问 URL。旧版 JSON 文本请求仍兼容。

图片请求经 Nginx 时允许最大 22 MiB 请求体，为 20 MiB 图片和 multipart 字段留出空间。单张限制由服务端上传拦截器和消息校验共同执行。

## 验证

E2E 冒烟会验证错误图片内容被拒绝、启用识图的模型可接受图片、SSE 返回图片元数据、历史记录保留附件，以及预签名对象可以读取。远程验证还应确认超大图片被拒绝、纯文本聊天仍通过。
