# AI 聊天上下文管理

## 模型配置

管理员在“模型与供应商 → 平台模型”中为每个聊天模型配置“上下文窗口（输入 + 输出 Token）”。新模型默认 8192 Token；迁移时旧聊天模型按 `max(8192, 最大输出 Token + 1024)` 回填，管理员应根据实际上游规格核对并修改。

`maxTokens` 仍表示最大输出 Token。后端将输出上限从上下文窗口中预留出来，剩余部分作为输入预算。上游映射上的 `maxTokens` 可继续覆盖平台模型的输出设置。

## 用量估算与上下文选择

聊天页在模型栏显示估算的输入 Token、当前输入预算和模型完整窗口，并提示预留的输出 Token。估算会按文字内容、每条消息开销和图片附件计算；图片暂按每张 1000 Token 估算。不同模型和供应商的 tokenizer 不同，因此界面显示的是保守估算值。

发送消息时，后端从最新对话向前选择完整轮次，在预算内优先保留近期对话。超出预算的旧消息仍保存在聊天记录中，但本轮不会发送给模型；界面会显示被省略的消息条数。若最新一轮本身超过输入预算，后端会拒绝该消息并提示用户缩短内容或压缩旧对话。

## 压缩上下文

“压缩上下文”会调用当前选中的聊天模型，将较早对话整理成摘要，通常保留最近两轮原始消息；如果当前上下文已超出预算，则保留最近一轮以便压缩更多旧内容。长历史会分批压缩；后端把摘要存放在会话中，并标记已纳入摘要的旧消息，后续请求使用摘要和未压缩的近期消息。完整原始记录和图片不会删除，历史页面仍可查看。

压缩请求使用现有聊天 Provider 和钱包计费流程，按上游实际输入/输出 Token 结算。压缩失败会退回预扣，不更新摘要。图片模型会把旧图片一并交给支持识图的模型；纯文字模型收到的是图片附件说明。

## API

- `GET /chat/context?model=<平台模型名>&sessionId=<可选会话 ID>`：返回上下文窗口、输入预算、估算用量、省略消息数、已压缩消息数和是否可压缩；不传会话 ID 时返回新对话的模型额度。
- `POST /chat/sessions/:id/context/compact`，请求体 `{ "model": "<平台模型名>" }`：压缩较早对话并返回更新后的上下文用量。
- 两个接口都要求登录，并验证当前用户拥有该会话。

上下文窗口保存在 `PlatformModel.contextWindowTokens`；摘要和消息压缩标记分别保存在 `ChatSession.contextSummary` 与 `ChatMessage.contextCompacted`。数据库迁移只增加字段，不改动既有聊天内容。

## 验证范围

应覆盖模型配置和迁移默认值、最近完整轮次选择、估算用量、会话所有权、长历史分批压缩、压缩失败退款、压缩后历史记录保留，以及聊天流请求不超过输入预算。部署验证按项目约定使用远程隔离测试环境，先本地提交并推送，再由 `lch:/root/lumina` 拉取后运行测试与构建。
